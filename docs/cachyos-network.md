# Сеть Android в NexDroid

Проверьте, получил ли Android DHCP-адрес и выбрал ли он сеть по умолчанию.
Диагностика NexDroid отдельно показывает состояние моста `waydroid0`,
DHCP-аренду, маршрутизацию Linux и сеть по умолчанию в Android.

Для проверки выходного интерфейса подставьте текущий IPv4 Android из
`waydroid status` в команду:

```sh
ip -4 route get 1.1.1.1 from "$ANDROID_IP" iif waydroid0
```

Linux может направить этот трафик через Ethernet, Wi-Fi или VPN. Поле `dev`
показывает маршрут для выбранного адреса. При раздельных маршрутах VPN
проверьте адрес назначения, на котором возникает ошибка.

- UFW. «Исправить сеть» добавляет узкие правила DHCP и DNS для моста и
  разрешает пересылку из подсети Android через найденный выходной интерфейс.
  Если маршрут изменился после подключения VPN, запустите диагностику снова.
- nftables и iptables. Проверьте входящие правила для UDP 68 → 67 и
  TCP/UDP 53 к адресу моста. В активных цепочках пересылки разрешите исходящий
  трафик подсети Android на найденном интерфейсе и ответы установленных
  соединений. Учитывайте правила перенаправления DNS в других таблицах.
- firewalld. Проверьте зону `waydroid0`, доступ к DHCP и DNS хоста и политику
  пересылки между зоной моста и зоной выходного интерфейса.

Если Linux видит DHCP-аренду и маршрут, а Android не видит сеть по умолчанию,
проверьте состояние Android ConnectivityService. Android может сохранить
IP-адрес после перезапуска системных служб и потерять сетевой маршрут.
